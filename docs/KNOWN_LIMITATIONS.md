# Known limitations

1. **Derived task, not the official 148-class benchmark.** TCM-SD42 uses a fixed historical 42-class task based on original `syndrome` annotations; it is not the official normalized 148-class TCM-SD label space.
2. **Historical task construction used test-label support.** An internal dataset_stats.json reports 278 labels and 42 eligible/selected labels under train>=100, dev>=10, test>=10 with a top-50 cap. Independent reconstruction finds 278 raw strings in Train, 282 in the raw three-split union, and 278 after trailing-证 canonicalization; 43 eligible raw strings canonicalize to the frozen 42-label vocabulary. The summary field raw_label_count=278 remains ambiguous about counting stage. The historical task definition was test-informed at the label-support level. The 227-record difference between capped Train (19,352) and frozen Train (19,125) remains unresolved.

3. **Historical execution chain remains incomplete.** A copy of preprocess_tcm_sd_v4_topn.py was recovered in the private local evidence archive; its code canonicalizes the terminal 证 suffix before support counting/capping. The script is not redistributed here because it contains fixed private runtime paths and expects licensed source data at those paths. The contemporaneous 2026-05-07 stdout, complete historical source-label frequency table, and intermediate downstream training-cleaning output remain unavailable. The recovered code strengthens evidence for the preprocessing logic but does not prove the exact historical end-to-end execution or explain the 227-record Train difference.
4. **Training-development redundancy.** Fifty-four development instances were involved in train-development pairs with similarity >=0.95, including 18 exact duplicates. In a ZY-BERT sensitivity analysis, removing overlap-affected development instances reduced development Macro-F1 from 0.8056 to 0.7742. This can affect development-based checkpoint selection; its impact on other systems is not quantified.
5. **Patient-level independence cannot be established.** No reliable patient identifier is available. Text-level decontamination does not prove patient-disjoint partitions; record-level bootstrap and McNemar analyses cannot account for possible within-patient correlation.
6. **Class imbalance.** The primary 4,218-case test set is strongly imbalanced. Macro-F1 and Balanced Accuracy should be interpreted alongside Accuracy.
7. **Checkpoint-selection documentation differs from public artifacts.** The historical Qwen3 checkpoint was selected by development loss. The archived InternLM3 configuration specifies Stage-2 development loss, while the later official-selection account specifies development Macro-F1. A private author-side replay matched the retained final adapters to archived epoch-2 dev420 outputs byte-for-byte for all three seeds, and both reported criteria select epoch 2; nevertheless, the historical criterion discrepancy remains in the documentation. Public weights, per-epoch outputs and selection logs are not distributed, so an outside reader cannot repeat that replay from this repository alone.
8. **Historical baseline provenance differs.** The MacBERT fine-tuned checkpoint and epoch-level history remain missing; its frozen predictions can be rescored, but the original training run cannot be re-instantiated from the original weights. The early pilot archive contains the historical Qwen3 TCM-Mini-best adapter (SHA-256 `a80b261a36d79b7085f4b577f0eed291b570103e4a32edc13ca5e7a6dcde7daf`, matching its retained checksum) and the 4,452-row raw-output artifact (SHA-256 `9a02eca7394a599ead9db00c80bb16803c63dedf203bae9d4f8c644523c07042`, matching the server inventory). This confirms those artifacts are preserved in the early archive; the original inference command and per-record input hashes are still missing, so the complete output-to-checkpoint link remains incomplete. The two Stage-2 epoch adapters needed for a saved-state selection comparison were not found in the latest server audit.
9. **InternLM3 executed layer-freezing behavior differed from the locked design.** The protocol records intended ranges 31–42 and 16–42, but the executed script did not call the stage-2 unfreezing routine. The private code/weight audit reports that both stages updated only LoRA adapters in layers 31–47. The pre-freezing adapter count (52,297,728) is not the per-stage optimizer scope (reported as 18,522,112). This is an implementation deviation, not a retroactive change to the historical protocol.
10. **Qwen3 stage-2 optimizer scope versus saved checkpoint.** The historical code and saved adapter configuration support a stage-2 optimizer group containing 43,646,976 LoRA parameters plus 168,960 fp32 normalization parameters. The historical code and logs show that these Norm parameters were included in the Stage-2 AdamW group and that Stage-2 steps ran, but retained before/after tensors and optimizer state are unavailable to measure each parameter's exact numerical delta. Adapter-only saving omitted the Norm parameters, so the development-loss selection state differs from the saved/evaluated artifact. The early archive contains a checksum-verified TCM-Mini-best adapter, but its linkage to the current four-system Qwen3 predictions is not proven; the two Stage-2 epoch adapters remain unavailable in the latest targeted audit. See `docs/QWEN3_STAGE2_SEMANTICS.md`.
11. **No public per-case predictions or raw records.** Aggregate metrics and confusion matrices are public. Re-running record-level pairing, duplicate-subset analyses or exclusion-set verification requires authorized local clinical inputs and frozen prediction files not distributed here.
12. **Clean-set internal duplicates remain.** The 4,218-record primary test set contains 12 exact-text duplicate groups (24 records, 12 redundant) and 22 normalized-text groups (45 records, 23 redundant; one group has discordant labels). Main metrics retain the frozen record-level set. The published aggregate sensitivity table reports changes after retaining the record with the smallest numeric ID suffix in each duplicate group; normalized-text removal (NFKC, consecutive digit runs deleted, then punctuation/symbol/control/whitespace removal) is a string-normalization stress test, not adjudicated semantic deduplication. These records can induce dependence not captured by record-level uncertainty estimates.
13. **The seed-7 prediction file has mixed decoding provenance.** An internal verification report describes a 739-record per-sample segment followed by a 3,479-record batch-8 continuation, and reports matching raw/parsed/clean IDs, order, gold labels, parser outputs and file hashes. The raw stdout and per-case files are not redistributed here. The continuation stdout was recovered in the 2026-10-23 targeted audit and its SHA-256 verified as `17eaf1e94b249e6bedd0645840553342c4687c2b890dafebbae31bf9a0dea36f`; it records batch size 8, 739 rows skipped and 3,479 generated. A prior reconciliation on a different server could not locate the referenced path, but the current audit reports the log bytes as FOUND/VERIFIED. The origin of the first 739 rows and the complete cross-segment checkpoint/tokenizer hash chain remain unverified. The completed full-run stdout and original argv were not preserved; the SEAL batch-size field is not independent proof of the runtime setting for all 4,218 records. Individual predictions cannot be attributed to a segment, and the test-set effect of batch-size differences is unknown. Batch-size-1 and batch-size-8 equivalence is not assumed.
14. **Text-level exclusion does not prove patient-level or semantic independence.** The frozen exclusion set contains 234 record IDs: six record IDs have raw exact-text matches representing five distinct raw-text hashes, and the remaining 228 IDs are the near-duplicate-only remainder in the historical record-level accounting. Earlier wording of 5 raw exact + 229 near mixed unique-text and record-level units. An alternative implementation with different text-normalization order overlapped with 226/234 IDs, with eight archived IDs not reproduced and three additional near-threshold candidates; this is a sensitivity warning, not an exact replay of the archived implementation. The private pair-level table and clinical inputs are not public, and the 0.95 threshold was not validated against expert-adjudicated duplicate pairs.
15. **No causal or clinical-deployment claim.** Systems differ in architecture, pretraining, tokenization, adaptation, rationale supervision and checkpoint-selection history. The study does not isolate a causal effect of domain pretraining or model scale and does not establish clinical safety, prospective effectiveness or deployment readiness.


**5-gram Jaccard diagnostic (not the historical production filter).** The completed log reports Dev/Test hits of 615/625 at threshold >=0.80, 516/550 at >=0.85, and 370/387 at >=0.90. Earlier interim values 502/518 and 424/447 came from an incomplete log tail and are superseded. These diagnostic hit counts do not reconstruct the historical deduplication operation.
