# Known limitations

1. **Derived task, not the official 148-class benchmark.** TCM-SD42 uses a fixed historical 42-class task based on original `syndrome` annotations; it is not the official normalized 148-class TCM-SD label space.
2. **Historical task construction used test-label support.** An internal `dataset_stats.json` reports 278 raw labels and 42 eligible/selected labels under train>=100, dev>=10, test>=10 with a top-50 cap. The original preprocessing source, full source-label frequency table and contemporaneous execution log were not recovered. Thus, 278 is a summary-file report value; neither the raw-label count nor the uniqueness of the historical threshold-based selection can be independently recomputed. Independent reconstruction from the current official source splits finds 278 raw strings in train, 282 in the raw three-split union, and 278 after trailing-证 canonicalization. The support thresholds select 43 eligible raw strings, which canonicalize to the frozen 42-label vocabulary. The retained summary's `raw_label_count=278` is therefore ambiguous about counting stage. The reconstruction yields 19,352/4,902/4,912 after the stated training cap, not the frozen downstream 19,125/4,411/4,452; the missing historical post-processing/deduplication script prevents explaining the differences. The historical task definition was test-informed at the label-support level.
3. **Historical preprocessing implementation unavailable.** The support rule is reported by retained secondary evidence, not independently verified from the original executing code. The independent reconstruction finds 43 eligible raw strings, which canonicalize to 42 labels; the top-50 cap is not binding because 43 is below 50. This reconstruction does not prove the same code ran historically.
4. **Training-development redundancy.** Fifty-four development instances were involved in train-development pairs with similarity >=0.95, including 18 exact duplicates. In a ZY-BERT sensitivity analysis, removing overlap-affected development instances reduced development Macro-F1 from 0.8056 to 0.7742. This can affect development-based checkpoint selection; its impact on other systems is not quantified.
5. **Patient-level independence cannot be established.** No reliable patient identifier is available. Text-level decontamination does not prove patient-disjoint partitions; record-level bootstrap and McNemar analyses cannot account for possible within-patient correlation.
6. **Class imbalance.** The primary 4,218-case test set is strongly imbalanced. Macro-F1 and Balanced Accuracy should be interpreted alongside Accuracy.
7. **Checkpoint-selection mismatch.** The historical Qwen3 checkpoint was selected by development loss, whereas the latest author-reported InternLM3 selection account specifies development Macro-F1. Public seals do not independently prove the InternLM3 ranking criterion; the underlying selection records are not redistributed.
8. **Historical baseline provenance differs.** The MacBERT fine-tuned checkpoint and epoch-level history remain missing; its frozen predictions can be rescored, but the original training run cannot be re-instantiated from the original weights. A prior private server inventory reported a Qwen3 adapter hash (`a80b261a36d79b7085f4b577f0eed291b570103e4a32edc13ca5e7a6dcde7daf`), but the 2026-10-23 targeted audit could not locate the selected adapter or epoch adapters and found the `TCM-Mini-best` link dangling. These reports conflict; adapter recovery and saved-state epoch comparison remain unverified until the bytes are found and hashed in the same environment. The original inference command and per-record input hashes also remain missing.
9. **InternLM3 executed layer-freezing behavior differed from the locked design.** The protocol records intended ranges 31–42 and 16–42, but the executed script did not call the stage-2 unfreezing routine. The private code/weight audit reports that both stages updated only LoRA adapters in layers 31–47. The pre-freezing adapter count (52,297,728) is not the per-stage optimizer scope (reported as 18,522,112). This is an implementation deviation, not a retroactive change to the historical protocol.
10. **Qwen3 stage-2 optimizer scope versus saved checkpoint.** The historical code and saved adapter configuration support a stage-2 optimizer group containing 43,646,976 LoRA parameters plus 168,960 fp32 normalization parameters. The historical code and logs show that these Norm parameters were included in the Stage-2 AdamW group and that Stage-2 steps ran, but retained before/after tensors and optimizer state are unavailable to measure each parameter's exact numerical delta. Adapter-only saving omitted the Norm parameters, so the development-loss selection state differs from the saved/evaluated artifact. The selected and epoch adapters are not currently locatable in the latest targeted audit. See `docs/QWEN3_STAGE2_SEMANTICS.md`.
11. **No public per-case predictions or raw records.** Aggregate metrics and confusion matrices are public. Re-running record-level pairing, duplicate-subset analyses or exclusion-set verification requires authorized local clinical inputs and frozen prediction files not distributed here.
12. **Clean-set internal duplicates remain.** The 4,218-record primary test set contains 12 exact-text duplicate groups (24 records, 12 redundant) and 22 normalized-text groups (45 records, 23 redundant; one group has discordant labels). Main metrics retain the frozen record-level set. The published aggregate sensitivity table reports changes after retaining the record with the smallest numeric ID suffix in each duplicate group; normalized-text removal (NFKC, digit runs replaced by `#`, then punctuation/symbol/control/whitespace removal while preserving `#`) is a string-normalization stress test, not adjudicated semantic deduplication. These records can induce dependence not captured by record-level uncertainty estimates.
13. **The seed-7 prediction file has mixed decoding provenance.** An internal verification report describes a 739-record per-sample segment followed by a 3,479-record batch-8 continuation, and reports matching raw/parsed/clean IDs, order, gold labels, parser outputs and file hashes. The raw stdout and per-case files are not redistributed here. The continuation stdout has now been recovered and its SHA-256 verified; it records batch size 8, 739 rows skipped and 3,479 generated. The origin of the first 739 rows and the complete cross-segment checkpoint/tokenizer hash chain remain unverified. Individual predictions cannot be attributed to a segment, and the test-set effect of batch-size differences is unknown.
14. **Text-level exclusion does not prove patient-level or semantic independence.** The 234-record exclusion set can be re-derived when the authorized private split files and archived near-duplicate pair table are supplied to the published scripts. Those clinical inputs and pair-level text records are not included in this repository. The 0.95 threshold is an inherited operational cutoff, not a threshold validated against expert-adjudicated duplicate pairs.
15. **No causal or clinical-deployment claim.** Systems differ in architecture, pretraining, tokenization, adaptation, rationale supervision and checkpoint-selection history. The study does not isolate a causal effect of domain pretraining or model scale and does not establish clinical safety, prospective effectiveness or deployment readiness.
